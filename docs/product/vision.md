# audiobook · 产品定位

从 `PRD.md` 和 `需求.md` 提炼。两边有冲突的句子放在待确认，没有折中。

## 一句话

把 PDF 和网页变成可以按段听的有声书，用参考音合成，在 Web 播放器里管理。

## 目标用户与核心场景

| 用户 | 场景 | 现在怎么做 | 痛点 |
| --- | --- | --- | --- |
| 想把资料听完的人（PRD 的用户画像） | 导入 PDF 或网页，听章节 | 整篇丢给语音合成 | 音频太长，失败了不好重来 |

## 成功的样子（可测量）

- 待确认：PRD 没有写可测量指标。

## 非目标（明确不做）

- 输入不是 PDF 或网页 HTML 的格式，本阶段不做（需求.md「已决定」）。
- 不支持人工标注章节（需求.md「已决定」）。
- 不生成整本书一条长音频（需求.md「已决定」）。
- 本阶段做不做声音模型训练：待确认。PRD 把它写成后续能力，需求.md 写成明确不做。

## 设计原则（≤ 5 条，冲突时按序取舍）

1. 先有 Web 播放器，再谈别的客户端（需求.md；代码里已经有 `client/macos`，算不算本阶段待确认）。
2. 缺参考音或缺 Index-TTS 地址就失败，不换一段默认声音。
3. 单次合成不超过 500 字，长章节先切开（`src/paragraphs.js`）。
